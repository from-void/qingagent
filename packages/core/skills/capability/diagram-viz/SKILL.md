# 图表可视化

本技能只负责文档里的确定性图表（Mermaid 与 draw.io），不负责照片、装饰插画、图标或自由构图 SVG。创建或修改图表前，先完成以下裁决，再只读取所选引擎子技能的 `SKILL.md`；不要把两个子技能无差别塞进上下文。

## 一、先判断值不值得画

- 默认克制。只有流程、关系、层次、时序、状态或空间部署用图明显比正文更清楚时才画。
- 单纯数值趋势、精确数值对比优先用表格；组成占比可用 Mermaid `pie`。不要硬套未支持的折线、柱状、散点语法。
- 信息不足以形成稳定节点和连线时先写文字，不为“看起来丰富”造图。
- 用户只要 Mermaid/draw.io 源码且明确不要渲染时，用代码块交付源码，不创建文档图表块。

## 二、选择引擎

- **单独画图先问引擎（铁则）**：用户单独发起画图请求且未点名引擎时，必须先单独调用 `askUserQuestion`，只问一句：“用 Mermaid（自动布局，适合流程/时序/状态，改起来省心）还是 draw.io（手工可编辑画布，适合架构/拓扑/自由排版）？”等待用户选择后再画，不得替用户默认决定。
- **只有三个豁免**：用户已点名引擎；写文章时顺带配图（按本节现有裁决自动选）；用户说过“别问”“直接画”或明确同义要求。除此之外不得跳过反问。
- 流程、时序、状态、类、ER、甘特、饼图、脑图：选 Mermaid，读取 `mermaid/SKILL.md`。
- 网络拓扑、部署、系统架构、工程框图、容器分组、精确坐标、复杂连线：选 draw.io，读取 `drawio/SKILL.md`。
- 纯流程/层级关系且节点超过 20 个时优先建议 Mermaid，以自动布局避免重叠；只有用户明确要求 draw.io 或需要手工编辑画布时才用 draw.io，并严格执行 `drawio/SKILL.md` 的布局防重叠铁则。
- 同一张图只选一个引擎。用户点名引擎时优先服从；若点名引擎无法表达目标，说明原因后改用另一引擎或表格。
- 选定后还要读取 `references/palettes.md` 中该引擎的映射；需要完整结构范本时再读 `references/templates.md` 的对应小节。

## 三、选择风格预设

- 默认：正式文档用「青简纸墨」。
- 多分区且要突出类别：用「经典」。
- 汇报、评审、管理层材料：用「商务」。
- 论文、学术、黑白打印：用「极简」。
- 头脑风暴、轻松说明：用「手绘水墨」。
- 用户点名风格或已有图使用某套风格时，用户要求与既有一致性优先。

## 四、上色方法论

1. 先数层、分支、类别或阶段等语义分组，全图取 2–4 个组色；同组同色同形。
2. 外重内轻：分组容器用浅色填充、深色描边；组内节点用白底或所选色板规定的浅中性底（如青简纸墨的纸色底），以色板 token 表为准；节点使用分组色描边。严禁逐节点填彩。
3. 连线一律使用所选色板的专属灰，不与节点争夺注意力。
4. 节点必须有 2px 边框，圆角统一为 8；有连线时节点间距至少 40。正文至少 14，标题至少 24，辅助文字 13 且用辅助灰。
5. 色彩遵守 60–30–10：中性底约 60%，组色约 30%，强调色不超过 10%；文字与底色对比至少 4.5:1。
6. draw.io 坐标和尺寸取 20 的倍数，标准节点 160×60，层间距至少 120、同层间距至少 60；边用正交线，标签白底并设置偏移。
7. Mermaid 每个节点都必须挂到某个 `classDef` 类（用 `class` 语句逐节点点名），未挂类节点会吃主题默认底色、破坏整板。init 的 `clusterBkg` / `clusterBorder` 提供全图分区默认色；需要按语义给不同分区着色时，必须先给 `subgraph` 稳定 ASCII id，再用 `style 分区id fill:#浅色,stroke:#深色` 精确覆盖。分区 `style` 只使用画布已保真支持的 `fill`、`stroke`、`color`、`stroke-width`；不要写 `stroke-dasharray`、节点几何或字号属性，这些会让可视化编辑器降级为 Mermaid 预览。

## 五、六组错误与正确

- 错：每个节点一种填充色。对：按 2–4 个语义分组分色，同组节点白底、同色描边。
- 错：容器和内部节点都用重色填充。对：容器浅填充加深描边，内部节点白底。
- 错：用彩色连线表达类别。对：类别由节点/容器表达，所有连线统一使用专属灰。
- 错：节点无边框，只靠底色区分。对：每个节点都有 2px 组色边框和统一 8 圆角。
- 错：未选择极简预设却全图黑白灰、没有视觉层级。对：保留中性底，以 2–4 个低饱和组色和不超过 10% 的强调色建立层级。
- 错：节点放错语义分组——服务节点装进数据层容器、数据库漂在容器外。对：每个节点必须归属语义正确的层容器，存储组件必须落在数据层容器内，层名与成员语义一一对应。

## 六、交付纪律

- Mermaid 用 `<mermaid>…</mermaid>`，draw.io 用 `<drawio>…</drawio>`；两者都是文档 `diagram` 块，不放进 `<pre>`。
- 任何规模的图都必须通过 `writeDraft` / `editDraft` 落入文档；严禁在聊天回复里直接手打整段 XML 或 Mermaid 长源码。
- 单图节点建议不超过 25 个；更大规模应按层拆成多张图（每层一张），或先出骨架图，再用 `editDraft` 增量补充节点。
- 保留既有节点、实体、状态、mxCell 与边的稳定 id；只改必要 label、边、样式或结构。
- 生成后按对应引擎真实语法检查；只有渲染成功的图才能计入完成摘要。
- 不要把图表职责转给 `generateSvg`；装饰性插画和自由构图另走生图技能。
