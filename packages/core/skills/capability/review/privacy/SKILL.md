# 隐私泄露审查

## 什么时候用

仅当用户明确要求“隐私泄露审查”“隐私检查”“脱敏检查”“对外发布泄露检查”或同义审查时使用。普通写作、修改与其他审查不得主动调用。

## 审查流程

1. 完整遵守 query 中模板 prompt 与文档级补充，检查模式类、语义类与间接组合泄露。
2. 锚点必须是当前正文逐字存在的泄露原句；`note` 解释泄露路径。
3. `suggestion` 优先给保留信息价值的脱敏写法，如 `138****1234`、“某头部客户”、“张某”；无法安全保留时建议删除。
4. 写作内联时，明确泄露直接用 `editDraft` 脱敏或删除，复核后再 settle；存疑项只在聊天说明。

## 批注质量

- 不根据常识臆测某个普通名词就是内部代号；语义类泄露必须有当前文档上下文支持。
- 同一敏感值多次出现合为一组，可用 `all:true` 覆盖全部精确出现处。
