# 来源审查

## 什么时候用

仅当用户明确要求“来源审查”“来源核查”“核对依据”“是否按素材写”或同义的素材对照核查时使用。普通写作、修改、润色及其他审查都不得主动调用本流程或 `create_annotation_groups`；但用户在最初写作请求里明确要求“写完做来源核查”时，按下方写作内联形态执行。素材是唯一 ground truth，默认不联网。

## 两种执行形态

1. **单独审查当前文档**：纯批注模式，不改稿，按下方流程产出批注组。
2. **写作流程内联审查**：`writeDraft` 产出候选后同回合 `readDraft` 候选并对照素材。确认的来源问题直接 `editDraft` 修复，修复后重新读取复核，再让候选 settle；不得先交初稿、不得为已修复问题创建批注。素材是否采用等需要用户裁量的覆盖率发现，只在聊天里克制说明。

## 审查流程

1. 调用 `readDraft` 读取当前文档全文。收到“[正文已更新]”提示时必须先重新 `readDraft`，不得沿用历史读取结果。
2. 查看当前会话的素材上下文，并逐份调用 `readMaterial` 读取相关素材全文。若当前会话没有素材，立即停止，不调用 `create_annotation_groups`，聊天只提示：`当前会话没有可对照的素材,请先添加素材再做来源审查`。
3. 从文档抽取可由素材核验的事实断言，优先检查数字、百分比、日期、金额、单位、量级、约数和统计口径。
4. 同时做正向溯源与反向覆盖率核查，只能作以下五类判定：
   - **有据**：素材直接支持该断言；不创建批注，不打扰用户。
   - **口径漂移**：素材值或口径与文中不一致；把能证明差异的素材原句逐字填入 `materialQuote`。
   - **无据**：已查完相关素材仍找不到支持；只有素材确实查不到时才能判定，严禁凭空把素材里可查到的内容判为无据。
   - **数字失真**：单位、量级或约数表达错误；把素材原句逐字填入 `materialQuote`。
   - **素材遗漏**：素材中的核心数据、重要经历或关键结论对主题重要，但文章没有采用；把素材原句逐字填入 `materialQuote`，并把批注锚在最相关章节标题的精确文字上。
5. 单独审查时只把口径漂移、无据、数字失真、素材遗漏交给 `create_annotation_groups`。同一断言在正文多处出现时合为一组，`anchors` 使用正文中的精确文本作为 `find`，需要覆盖全部相同出现处时设置 `all:true`。每组写清 `summary`、`judgment`、判定与依据 `note`、`origin:"source-check"`，可给出对齐素材的 `suggestion`。`summary` 只写变更类型短标题且不超过 15 字（如“履历时间与素材不符”“金额口径漂移”），细节解释一律写进 `note`。`materialQuote` 必须是 `readMaterial` 返回文本中逐字存在的片段，严禁虚构“脱敏”“红字”“***”等标记；无据类填写 `checkedScope` 说明核查范围，不得填写引句。模板要求分级时原样填写 `severity`；默认口径是数字失真与无据=`error`、口径漂移=`warn`、素材遗漏=`info`。
6. query 中的“来源审查指令”是用户长期偏好，必须完整遵守；补充要求只约束本次审查。
7. 完成后聊天只回复一句总括和一张简表，列为“断言 / 判定 / 依据”。不得长篇复述素材或正文；“有据”断言不进入表格。

## 批注质量

- 锚点必须逐字存在于当前正文；不得用改写后的文本或整段模糊文本代替。
- 口径漂移、数字失真与素材遗漏必须提供可逐字验证的 `materialQuote`；无据项要通过 `checkedScope` 明确说明已核查的素材范围，不得伪造引文。
- 没有问题时不调用 `create_annotation_groups`，只用一句话说明已按素材核查且未发现来源问题。
- `create_annotation_groups` 返回参数解析失败时，必须拆成小批重试（每次≤3组），不得空手结束。
